# Dashboard 顶部横向导航设计

## 背景

当前 Dashboard 将功能导航纵向放在页面左侧。知识库内容本身已经采用左右分区，纵向导航会继续压缩可展示宽度，使统计卡、行动建议和详情区域过早换行。

## 目标

把 Dashboard、Inbox、Projects、Knowledge Map、Health、Action Guide 和 Settings 统一移动到页面顶部横向导航栏，释放左侧空间，让主内容区域尽可能宽。

## 布局

```text
┌─────────────────────────────────────────────────────────────┐
│ Dashboard |  Inbox | Projects | Knowledge Map | ...  | 设置 │
├─────────────────────────────────────────────────────────────┤
│                 Dashboard 主内容左右分区                    │
│          左侧主要内容                 右侧辅助信息           │
└─────────────────────────────────────────────────────────────┘
```

- 顶部导航位于 Dashboard 内容容器内部，不占用 Obsidian 左侧边栏。
- 不展示 `AI Knowledge OS` 品牌块，左端直接固定展示 Dashboard。
- 中间区域依次展示 Inbox、Projects、Knowledge Map、Health 和 Action Guide，并独立承担横向滚动。
- Settings 固定在导航最右端，不进入中间滚动区域；以后增加更多功能项时，Settings 仍始终可见且不会被覆盖。
- 当前页面使用紫色激活态，其他按钮保持轻量边框和悬停反馈。
- 主内容从导航下方开始，占用容器完整宽度；内部各页面的数据和操作逻辑不变。

## 颜色规范

导航与 Dashboard 新增样式仅使用以下色值：

| 用途 | 色值 | RGB | CMYK |
|---|---|---|---|
| 边框、柔和分隔 | `#E1BEE7` | 225, 190, 231 | 2.6, 17.75, 0, 9.41 |
| 浅色激活背景、悬停背景 | `#F3E5F5` | 243, 229, 245 | 0.82, 6.53, 0, 3.92 |
| 导航与内容表面 | `#FFFFFF` | 255, 255, 255 | 0, 0, 0, 0 |
| 主强调色、激活文字或指示线 | `#BA68C8` | 186, 104, 200 | 7, 48, 0, 21.57 |

文字主体继续继承 Obsidian 主题颜色，以保证明暗主题可读性；上述四种颜色负责导航背景、边框和交互强调。

## 响应式行为

- 宽窗口保持单行导航。
- 宽度不足时只有中间功能区域允许横向滚动，按钮不压缩成难以点击的宽度。
- Dashboard 始终固定在左侧，Settings 始终固定在右侧，两者不参与滚动。
- 不恢复左侧纵向菜单，不把功能项折叠成需要额外点击的下拉菜单。
- 主内容原有左右分区在自身断点下响应式调整，导航不参与其列宽计算。

## 实现边界

- 只调整 Dashboard DOM 容器结构与 CSS，不改变页面名称、切换逻辑、Store、DeepSeek、设置或数据源行为。
- 保持 Dashboard 标签固定、启动不抢焦点、文件列表原生替换行为不变。
- 为最终源码契约增加布局断言，防止以后重新引入左侧固定列。

## 验收标准

- 所有功能切换按钮在页面顶部横向排列。
- Dashboard 固定在左侧，Settings 固定在右侧，中间新增功能不会覆盖二者。
- 页面不再展示 `AI Knowledge OS` 品牌块。
- Dashboard 左侧不再存在独立导航列。
- 主内容宽度明显增加，现有左右分区拥有完整容器宽度。
- 窄窗口可以横向滚动导航，功能按钮仍可访问。
- 导航交互色符合 `#E1BEE7`、`#F3E5F5`、`#FFFFFF`、`#BA68C8` 规范。
- 现有自动测试、构建、安装哈希校验和 Obsidian 启动回归继续通过。
