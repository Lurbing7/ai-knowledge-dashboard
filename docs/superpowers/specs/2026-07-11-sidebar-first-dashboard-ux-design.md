# 面向 Obsidian 侧栏常开习惯的 Dashboard UX 设计

## 背景

当前 Dashboard 的视觉结构按宽屏独立页面设计，但用户实际长期打开 Obsidian 左侧文件边栏和右侧大纲边栏。中央叶子是主要工作区，其宽度会在不改变整个应用窗口宽度的情况下明显缩小。

现有实现因此产生四个问题：

1. 大面积 Hero 只展示产品名称和说明，占用首屏高度，没有帮助用户决定下一步。
2. 领域概览固定使用四列，并通过 viewport media query 响应；Obsidian 侧栏只缩小中央叶子，不一定触发 viewport 断点，导致标题被过度省略。
3. “查看全部”使用普通 button 元素，仍受 Obsidian 主题的阴影、最小高度和按钮外观影响，形成紧贴文字的小按钮和底部空占位。
4. Health 摘要被放入 `<pre>`，Markdown 标题、列表、链接没有经过 Obsidian 渲染。

此外，导航顺序把知识整理入口放在行动入口之前，不符合“行动建议服务当前现实主线，知识库维护按需进行”的优先级。

## 目标

- 把左右边栏常开时的中央叶子作为默认布局环境。
- 让“下一步行动”成为 Dashboard 第一内容和第二导航入口。
- 删除不提供决策价值的 Hero 色块。
- 保证领域卡片在中央区域缩窄后仍能展示可辨识的笔记标题。
- 使用 Obsidian 原生 Markdown 渲染 Health 摘要。
- 保持现有 DeepSeek、数据源、SecretStorage 和新标签页打开笔记的行为不变。

## 非目标

- 不增加新的知识库统计或 AI 数据源。
- 不把 Dashboard 改成完整文件管理器。
- 不根据整个显示器或浏览器 viewport 猜测中央叶子宽度。
- 不在本轮修改 DeepSeek 提示词、Thinking 设置或行动建议数据模型。
- 不修改用户的 Obsidian 左右边栏状态。

## 信息架构

### 顶部导航

固定顺序调整为：

1. Dashboard
2. Action Guide
3. Projects
4. Inbox
5. Knowledge Map
6. Wiki
7. Health
8. Settings（继续固定最右）

Action Guide 放在 Dashboard 之后，表示下一步行动是系统第二优先入口。Projects 位于 Inbox 之前，表示现实项目与求职行动优先于收集箱维护。

导航继续横向滚动，Dashboard 与 Settings 固定在两侧；中间项目在空间不足时滚动，不压缩成难以点击的窄按钮。

### Dashboard 内容顺序

删除 `.akd-hero` 整个区域。Dashboard 主体顺序调整为：

1. 下一步行动区域：数据来源、用户画像授权、生成按钮、生成状态和行动建议。
2. 知识领域概览标题。
3. Inbox、Domain、Projects、Wiki 四张概览卡片。
4. 配置或数据刷新问题靠近相关区域显示，不占据无错误时的空间。

下一步行动区域使用普通 Obsidian 页面表面色和轻量边框，不再用大面积强调色。薄荷绿仅用于生成按钮、状态和局部强调。

## 容器响应式布局

响应式判断以 Dashboard 中央内容容器为基准：

- `.akd-main` 声明 `container-type: inline-size`。
- 默认领域概览为两列。
- 当中央内容容器小于等于 760px 时切换为单列。
- 不再为领域卡片提供四列模式。

这样即使整个 Obsidian 窗口很宽，只要左右边栏把中央叶子压窄，卡片就会自动切换为单列。

移动端和极窄区域继续使用现有全宽布局；顶部导航允许横向滚动。

## 领域卡片

### 结构

每张卡片按以下顺序显示：

- 标题行：领域名称、笔记总数、右侧 `查看 →`。
- 事实信号：最近变化、最近沉淀或 Wiki 时间信号。
- 最近 3 篇笔记。

`查看 →` 移到标题行，不再占用卡片底部高度。它仍可使用 button 语义以支持键盘操作，但必须完全重置主题按钮外观：无边框、无阴影、无固定最小宽度和高度，呈现为文字链接。

### 最近笔记

最近笔记行继续可点击并在新标签页打开，但视觉改为列表项：

- 标题最多显示两行，不再强制单行省略。
- 使用 `overflow-wrap: anywhere` 处理长英文、文件编号和无空格标题。
- 修改时间放在标题下方或独立次要行，不与标题争抢水平空间。
- DOM 的 `title` 属性保留完整笔记名称，鼠标悬停可查看完整标题。
- 列表项完全移除 Obsidian 默认 button 阴影与凸起外观。

卡片不设置为了对齐而产生的大块固定最小高度；两列布局中的高度由内容自然决定。

## Health 页面

Health 继续只展示经过数据边界筛选的“结论”和“维护信号”摘要，但使用 `MarkdownRenderer.render` 渲染到普通内容容器：

- Markdown 标题、列表、强调和内部链接使用 Obsidian 原生样式。
- 渲染调用使用配置中的 Health 文件路径作为 source path，使内部链接能够正确解析。
- 页面提供“打开 Health 原文”文字入口，并继续在新标签页打开原笔记。
- 数据源关闭、文件缺失或摘要为空时沿用现有明确空状态。

不直接展示完整 Health 文件，也不改变 Wiki 编译或 Health 生成流程。

## 视觉原则

- 页面主要表面继续继承 `--background-primary` 与 `--background-secondary`。
- 薄荷绿只表达当前导航、生成操作和健康状态，不再承担大面积背景。
- 卡片边界靠轻边框和间距区分，避免密集阴影。
- Action Guide 与 Dashboard 中的行动区域保持一致样式，降低页面切换认知成本。
- 所有按钮和链接必须在 Obsidian 默认主题、浅色主题和深色主题下可辨识。

## 数据与隐私边界

本轮只调整布局和渲染，不改变本地快照和 DeepSeek 上下文：

- 最近笔记标题与路径仍只用于本地 Dashboard。
- Health 仍只读取已批准的摘要章节。
- 用户画像和求职状态不新增到任何公共输出、日志或 PR 描述。
- `data.json` 继续作为本地运行状态，不纳入本轮插件源码改动。

## 测试策略

### 源码契约

- DashboardView 不再包含 `akd-hero`。
- 导航数组中 Action Guide 紧跟 Dashboard，Projects 位于 Inbox 之前。
- Dashboard 在领域卡片之前渲染行动区域。
- Health 使用 `MarkdownRenderer`，不再创建 `pre.akd-health-summary`。
- 领域卡片包含标题行 `查看 →` 和最近笔记完整 title 属性。

### CSS 契约

- `.akd-main` 包含 `container-type: inline-size`。
- 领域卡片默认两列，并在 `@container (max-width: 760px)` 下切换为一列。
- 不再存在 `repeat(4, ...)` 的领域布局。
- 最近笔记标题支持两行和 `overflow-wrap`。
- `akd-area-link`、`akd-recent-note` 明确移除 box-shadow、最小按钮尺寸和默认外观。

### 手动验收

在 Obsidian 中验证三种状态：

1. 左右边栏关闭：领域卡片两列，标题可读。
2. 左右边栏同时打开：中央叶子根据实际宽度保持两列或自动切换单列，没有横向挤压。
3. 中央叶子进一步缩窄：单列卡片、导航横向滚动、设置按钮仍固定右侧。

同时验证 Health 标题、列表和内部链接已渲染，并能打开原文。

## 验收标准

- 首屏不再出现无信息价值的大面积 Hero。
- Dashboard 和顶部导航均先呈现行动，再呈现知识整理入口。
- 左右边栏常开时，最近笔记标题至少可显示两行，查看入口不再像默认按钮。
- 领域布局由中央容器宽度驱动，默认两列，窄于 760px 自动单列。
- Health 摘要呈现为 Obsidian 渲染后的 Markdown，而非原始文本。
- 自动化测试、TypeScript 检查、构建、本地安装和运行时哈希验证通过。
- 本轮从合并后的 `main` 创建新分支和新 PR。
